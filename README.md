# 혈당코치 우땅이

당뇨 식사 관리를 도와주는 RAG 챗봇입니다. 가이드라인 문서에서 식사 방법을 찾아 알려주고, 음식 이름으로 영양성분과 혈당 부담 정도를 계산합니다.
숫자와 등급은 전부 코드가 계산하고, LLM은 결과를 문장으로 풀어 쓰는 역할만 합니다.

> 혈당 부담 등급은 순탄수화물 기준의 **임시 기준**이며, 혈당 수치를 예측하지 않는 참고용입니다. 의료적 판단을 대신하지 않습니다.

## 기능

| 기능 | 설명 | 구현 |
| --- | --- | --- |
| 식사 방법 물어보기 | 가이드라인 문서를 검색해 근거와 함께 답변, 조건에 맞는 메뉴 추천과 대체 메뉴 | `guideline_rag.py`, `nutrition_tools.py` |
| 혈당 부담 확인 | 음식 하나의 열량, 탄수화물, 순탄수를 계산하고 낮음/보통/높음으로 표시 | `nutrition_tools.py` |
| 한 끼 합산 | 여러 음식을 묶어 합계로 등급을 계산하고 가장 부담이 큰 음식을 알려줌 | `nutrition_tools.py` |
| 하루 식사 기록 | 끼니별로 기록하고 하루 합계를 보여줌 (접속자별로 분리 저장) | `nutrition_tools.py` |

보조 라벨로 열량·당류·나트륨도 표시합니다. 식약처 1일 기준치를 3끼로 나눈 자체 참고 기준이며, 높음일 때만 언급합니다.
자세한 동작은 [기능 2·3·4 구현 상세](docs/features_2_3_4_detail.md)를 참고하세요.

## 구조

```
src/         nutrition_tools.py, guideline_rag.py, guideline_tools.py
notebooks/   chatbot_demo_langchain(챗봇), retrieval_eval_bm25_reranker(검색 평가), cuisine_tagging(요리 종류 태깅)
data/        master.parquet (음식 516개)
docs/        구현 상세, 평가 결과
```

- 챗봇은 도구 호출(tool calling) 에이전트(`gpt-4o-mini`)이며, 앞단에 규칙 기반 안전 필터가 있습니다.
- 검색은 LangChain + FAISS(`text-embedding-3-small`)이고, 상황·대상 태그로 점수를 가감합니다.
- 답변의 출처 표기는 LLM이 아니라 코드가 실제 호출된 도구를 보고 붙입니다.

## 실행 방법

Google Colab 기준입니다.

1. `OPENAI_API_KEY`를 Colab 보안 비밀(Secrets)에 등록하고 해당 노트북의 접근 권한을 켭니다.
2. 코드와 데이터를 드라이브에 올리고, 노트북 설정 셀의 경로(`TOOL_DIRS`, `MASTER_PATH`, `DOCS_DIR`)를 본인 환경에 맞게 바꿉니다.
3. `notebooks/chatbot_demo_langchain.ipynb`를 위에서부터 실행합니다.

가이드라인 원문과 식약처 원본 엑셀은 이 저장소에 포함하지 않습니다. 출처는 아래를 참고하세요.

## 평가 결과

### 검색 방식 비교 (질문 60개, 상위 4개, LLM이 답이 되는지 판정)

| 방식 | Hit@4 | Precision@4 | MRR@4 |
| --- | --- | --- | --- |
| **현재 (FAISS + 가감점)** | **0.967** | 0.579 | 0.915 |
| Dense만 | 0.933 | 0.542 | 0.876 |
| BM25만 | 0.900 | 0.483 | 0.785 |
| Dense + BM25 (RRF) | 0.983 | 0.554 | 0.882 |
| (Dense + BM25) + Reranker | 0.950 | 0.608 | 0.906 |
| 현재 + Reranker | 0.967 | 0.671 | 0.931 |

- 정답 청크 1개만 인정하는 Recall은 낮게 나왔지만, 실패 사례를 열어보니 상위 4개가 답이 되는 내용인 경우가 대부분이어서 판정 방식으로 다시 측정했습니다.
- 리랭커(`BAAI/bge-reranker-v2-m3`)는 Precision을 올리지만 Hit는 같고 모델 크기와 응답 지연이 늘어나 적용하지 않았습니다.
- 문서 밖 질문 거절 기준(`min_score=0.30`)은 관련 질문 오거절 0%, 문서 밖 질문 80% 거절이었습니다.

### 도구 선택
음식 2개 이상 질문 10개에서 `meal_sum` 하나로 처리한 비율이 프롬프트 규칙 추가 후 90%에서 100%가 되었습니다.

## 데이터 출처

- 식약처 식품영양성분 DB (음식 영양성분)
- AI-Hub 음식 이미지 데이터셋의 음식 카테고리 (음식 이름 목록만 사용, 이미지는 포함하지 않음)
- 식사 가이드라인: 질병관리청 등 공개 문서 (원문은 포함하지 않음)
- 혈당 부담 등급의 참고 자료: 대한당뇨병학회 식품교환표(2023), 보건복지부 영양소 섭취기준(2025). 끼니별 낮음/보통/높음 구간이 직접 적힌 공식 자료는 없어 임시 기준으로 정했습니다.

`master.parquet`은 위 영양 DB와 음식 카테고리를 연결한 516개 음식 표입니다 (동일 370, 근사 106, 변형 40). `요리종류`(한식·중식·일식·양식·분식·기타) 열은 LLM으로 태깅한 뒤 직접 검수했습니다.

## 한계

- 등급 기준(순탄수 15g, 40g)은 임시값입니다.
- 다루는 음식이 516개라 DB에 없는 메뉴(예: 탕수육)는 답할 수 없습니다.
- "밥"이 현미밥 130g 기준의 근사 값이라 한 끼 합산이 작게 나옵니다.
- 하루 기록은 서버를 다시 시작하면 사라집니다.
- 100g 기준으로 저장된 음식은 메뉴 추천 후보에서 빠집니다.
