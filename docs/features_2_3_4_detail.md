# 민석 구현 파트: 기능 2·3·4 상세

코드는 모두 `민석_코드/nutrition_tools.py` 한 파일에 있고, 챗봇 노트북(10-3 셀)에서 얇은 래퍼 함수로 감싸서 LLM 도구로 등록해요. 이 파일은 API 키나 LLM 호출 없이 `master.parquet`만 읽어서 계산해요. 숫자와 등급은 전부 코드가 계산하고, LLM은 결과를 문장으로 풀어 쓰는 역할만 해요.

## 공통: 음식 찾기와 영양 계산

### 데이터
- `master.parquet`: AI-Hub 음식 카테고리 573개 중 영양DB와 연결된 516개 (동일 370 / 근사 106 / 변형 40), 영양 누락 0개
- 열: 음식명(`ai_hub_name`), 식품명, 기준(1인분 또는 100g), 1회제공량, 에너지, 탄수화물, 총당류, 총 식이섬유, 단백질, 지방, 나트륨, 근사표시

### 음식 이름 찾기 `find_food(master, query, n=5)`
사용자가 쓴 이름을 `food_id` 최대 5개로 바꿔요. 순서는 이래요.
1. 이름이 정확히 같은 음식 (AI-Hub 이름, 식품명 둘 다 검사)
2. 이름에 검색어가 포함된 음식 (이름이 짧은 순)
3. 그래도 5개가 안 되면 비슷한 이름 (`difflib`, 유사도 0.5 이상)

공백은 모두 지우고 비교해요. 맨 앞의 결과를 그 음식으로 보고 계산하고, 나머지는 "비슷한 이름"으로 보여줘요.

### 영양 계산 `nutrients(row, mult)`
기준량(1인분 또는 100g)에 먹은 양 배수 `mult`를 곱해요. 반만 먹으면 0.5, 곱빼기면 1.5예요. 값이 비어 있으면 0으로 처리해요.
- 순탄수화물 = 탄수화물 − 식이섬유 (0보다 작아지면 0)
- 열량, 탄수화물, 식이섬유, 당류, 단백질, 지방, 나트륨을 함께 돌려줘요.

### 등급 계산 `level_of(순탄수, 당류)`

| 순탄수화물 | 등급 |
| --- | --- |
| 15g 미만 | 낮음 |
| 15g 이상 40g 미만 | 보통 |
| 40g 이상 | 높음 |

여기에 당류 보정이 붙어요. 당류가 15g 이상이면 등급을 한 단계 올려요. 이미 높음이면 그대로예요. 등급이 오른 경우 이유 문구에 "당류 ○g로 많아 한 단계 올림"이 같이 붙어요.

기준값 15g과 40g은 공식 기준이 없어서 정한 임시값이에요. 화면에도 "임시 기준"이라고 표시해요. 참고한 자료는 대한당뇨병학회 식품교환표(곡류 1교환의 탄수화물 23g)와 보건복지부 영양소 섭취기준(탄수화물 에너지 비율 50~65%)이고, 끼니별 낮음/보통/높음 구간이 직접 적힌 자료는 찾지 못했어요. 코드에서는 `LEVEL_CFG` 한 곳만 고치면 전체에 반영돼요.

### 보조 라벨 `side_labels`
혈당 부담과 별개로 열량, 당류, 나트륨도 낮음/보통/높음으로 보여줘요. 식약처 1일 영양성분 기준치를 3끼로 나눠서 정한 자체 참고 기준이고, 공식 분류는 아니에요.

| 항목 | 낮음 | 보통 | 높음 |
| --- | --- | --- | --- |
| 열량 | 500kcal 미만 | 900kcal 미만 | 900kcal 이상 |
| 당류 | 10g 미만 | 35g 미만 | 35g 이상 |
| 나트륨 | 400mg 미만 | 1000mg 미만 | 1000mg 이상 |

챗봇은 이 중 "높음"인 항목이 있을 때만 한 문장으로 언급하고, 그때 "자체 참고 기준"이라는 안내 문구를 푸터에 붙여요.

## 기능 2. 혈당 부담 확인

음식 하나를 이름으로 물어보면 영양과 혈당 부담 등급을 알려줘요.

- **LLM 도구:** `check_food(food, amount)`
- **함수:** `lookup(master, food_id, mult)`
- **동작:** `find_food`로 음식을 찾고 → `nutrients`로 영양을 계산하고 → `level_of`로 등급을 계산하고 → `side_labels`로 보조 라벨을 붙여요.
- **돌려주는 값:** 음식명, 기준(예: "1인분 기준 (600g)"), 배수, 영양, 혈당 부담, 이유, 보조 라벨, 근사 여부와 안내 문구, 비슷한 이름 후보
- **근사 음식:** 영양DB에 정확히 같은 음식이 없어서 가장 가까운 음식 값을 쓴 경우예요. "가장 가까운 음식(○○) 기준이에요"라고 안내해요.
- **없는 음식:** "데이터에 없는 음식이에요"라고만 답하고, 숫자를 지어내지 않아요.

예시 (짜장면 1인분, 실제 도구 결과)
- 열량 529kcal, 탄수화물 86.2g, 식이섬유 8.2g, 당류 36.4g
- 순탄수 78g이라 혈당 부담 **높음**
- 나트륨 1,843mg이라 보조 라벨 나트륨 **높음**

## 기능 3. 한 끼 합산 평가

여러 음식을 한 끼로 묶어서 합계와 등급을 계산하고, 부담이 가장 큰 음식을 알려줘요.

- **LLM 도구:** `meal_sum(foods)` (음식 이름과 양 배수의 목록)
- **함수:** `meal_sum(master, items)`
- **동작:** 음식마다 `lookup`을 돌려서 영양을 모두 더하고, **합계**로 등급을 새로 계산해요. 음식별 등급을 평균내지 않아요. 한 끼의 순탄수 합계가 기준이라서, 낮음 음식 여러 개가 모여도 합계가 크면 높음이 나와요.
- **가장 부담이 큰 음식:** 노트북 래퍼가 음식별 순탄수를 비교해서 가장 큰 음식과 그 비중(합계 대비 %)을 계산해요.
- **일부 음식이 데이터에 없을 때:** 찾은 음식만 합산하고, 없는 음식은 따로 알려줘요.
- **100g 기준 음식:** "먹은 양에 맞게 배수를 조정하세요"라는 안내를 붙여요.
- **도구 선택 규칙:** 음식이 2개 이상이면 `check_food`를 따로 부르지 않고 `meal_sum` 하나로 계산하도록 시스템 프롬프트에 규칙을 넣었어요. 음식 2개 이상 질문 10개로 테스트했을 때 모두 `meal_sum`으로 처리됐어요. LLM이 항상 따른다는 보장은 없어서 한계로 봐요.

예시 (밥 + 김치찌개 + 계란말이)
- 열량 646kcal, 탄수화물 62.3g, 순탄수 52.7g, 당류 3.4g
- 한 끼 혈당 부담 **높음**
- 가장 부담이 큰 음식은 밥이고, 순탄수의 약 93%를 차지해요. (밥은 현미밥 기준의 근사 값)

## 기능 4. 하루 식사 기록

이미 먹은 음식을 끼니별로 저장하고, 하루 합계를 보여줘요.

- **LLM 도구:** `record_meal(meal, foods)`, `daily_summary()`, `remove_record(meal, food)`
- **클래스:** `DailyLog` (끼니는 아침, 점심, 저녁, 간식)
  - `add(끼니, food_id, 배수)`: 기록 추가
  - `remove(번호)`: 기록 삭제
  - `summary()`: 끼니별로 `meal_sum`을 돌리고, 전체 기록의 합계도 계산
- **기록하기:** 양을 말하지 않으면 1인분으로 바로 기록해요. 끼니를 알 수 없을 때만 어느 끼니인지 물어요. 저장 뒤에는 오늘 기록 요약을 같이 돌려줘요.
- **지우기:** 끼니와 음식 이름으로 조건을 걸어서, 맞는 기록을 모두 지워요. 이름은 일부만 맞아도 돼요.
- **등급은 끼니별로만:** 하루 합계에는 열량, 탄수화물, 순탄수, 당류, 나트륨 숫자만 보여줘요. 한 끼 기준 등급을 하루 전체에 적용하면 "하루 종일 높음"처럼 오해를 줄 수 있어서 의도적으로 뺐어요.
- **저장 범위:** 접속자(세션)마다 따로 보관해요(Gradio `gr.State`). 새 대화를 누르면 그 사람의 기록만 비워지고, 서비스를 다시 시작하면 모든 기록이 사라져요.

## 참고: 기능 1에서 쓰는 메뉴 검색 (민석 코드)

기능 1의 문서 검색은 태영 코드(`guideline_rag.py`)가 맡고, 조건 메뉴 추천과 대체 메뉴는 이 파일의 아래 함수를 써요.

- **`search_foods`:** 음식 종류 단어(국, 탕, 면 등), 탄수화물 상한, 열량 상한, 단백질 하한으로 DB를 거르고 탄수화물, 열량, 순탄수 순으로 정렬해요. "국"은 "국수"에 걸리지 않게 따로 처리했어요. 조건에 딱 맞는 메뉴가 없으면 숫자 조건을 풀고 가장 가까운 메뉴를 보여줘요.
- **`find_alternatives`:** 같은 상세분류(없으면 대분류)에서 순탄수가 더 적은 메뉴를 찾아요. 분량이 너무 작은 음식(과자 등)은 빼요. 원래 음식 분량의 50% 미만이거나 열량이 40% 미만이면 제외해요.

## 한계와 개선 방향

| 한계 | 개선 방향 |
| --- | --- |
| 등급 기준값(15g, 40g)이 임시 | 근거 자료를 더 찾아서 확정 |
| 다루는 음식이 516개 (예: 탕수육 없음) | 매핑 범위 확대 |
| 이름이 비슷한 다른 음식으로 잡히는 경우가 있음 (예: 제육볶음 → 볶음밥) | 별칭 사전 보강, 매칭 기준 강화 |
| "밥"이 현미밥 130g 기준의 근사 값이라 한 끼 합산이 작게 나옴 | 밥 항목을 따로 보정 |
| 100g 기준으로 저장된 음식(예: 깐풍기)은 메뉴 추천 후보에서 빠짐 | 1인분 환산 기준 추가 |
| 하루 기록이 서버를 다시 시작하면 사라짐 | 사용자별 저장소에 기록 보관 |
| 먹은 양은 "반만", "곱빼기" 같은 말을 LLM이 배수로 바꿔서 정확하지 않을 수 있음 | 양 입력 방식 보강 |
